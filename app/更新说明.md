# 1.3.0 更新说明

新增可选的能量平台连接与 TRC20 无感能量。**默认仍是独立本地模式**，旧配置无需绑定平台即可继续按原设置运行。

- 在“投放参数 → 能量平台连接”填写平台 HTTPS 地址及一次性绑定码，绑定当前投放钱包。绑定证明和交易签名均在本机完成，私钥不上传。
- 绑定后，在平台客户后台按地址切换“普通租赁 / 无感能量”。TCL 同步期望与生效模式，等待原交易安全结束后切换；保留扫描进度、等待队列和本次计数，不启动手动暂停的任务。
- 无感模式跳过原最低能量门槛及“单笔能量费上限 + 保留余额”的本地 TRX 门槛，改用平台逐笔资源判断，并继续共用地址原有的 TRX 停止线、恢复线及自动恢复开关。已有资源优先使用，不必等能量归零。签名交易的费用上限取平台与本地设置中较小者，原配置保留。
- 无感模式只忽略固定最低能量，不忽略平台 TRX 余额保护。例如停止线 15 / 恢复线 20 TRX：余额低于 15 时暂停新发送，回到 17 不恢复；开启自动恢复后，平台连续两次有效采样达到 20 才恢复。关闭自动恢复需在平台手动启用。原运行任务保留扫描、队列和计数，用户手动暂停的任务不会自行启动。
- 查询、扫描、构造及回执仍使用原查询 RPC。无感模式只将已签名交易交给平台分流，TCL 不直接请求供应商广播节点；普通模式继续本地广播。
- 已有资源直发不收无感服务费。无感补能路线在平台核实链上固化成功、准确转账及完整能量回执后，按接单时的售价收取一次服务费；等待确认时显示预留，结果未知不视为已扣款或零费用。具体售价以平台显示为准，例如 0.95 TRX/笔。
- 平台提交标记与原签名持久保存。提交响应丢失、断网或重启后只查原订单，绝不套用本地“最多 4 次”补试，也不换节点重发。准入容量等待发生在签名前，不消耗投放重试次数。
- 只有平台返回 HTTP 429，且明确包含 code=energy_capacity_wait 与 broadcast_started=false 时，才允许保持同一 intent、同一准入许可和同一签名交易，等待 1 秒加随机抖动后再次提交平台网关；总共最多 12 次提交（含首次）。每次等待后复核任务仍在运行、策略及版本未变化、准入许可和签名交易仍有效。普通 429、超时、断网或其他未知结果一律只查询原订单；此例外不重签、不换 intent，也不会由 TCL 重试供应商广播。
- 若平台以匹配本 intent 和准入许可的 HTTP 409 energy_trx_paused、broadcast_started=false 明确拒绝，表示该签名从未转发：TCL 保留审计并等待平台恢复，之后用同一 intent 取得新许可、重新签名；旧许可及旧签名不重播。其他 409、普通 429、超时及未知回复仍只查原单。
- 投放记录、统计和 CSV 分开显示链上费用与平台服务费。费用晚到仍归入原交易链上日期；待核对金额保持未知，不当作零。
- 长期未知交易经平台管理员核实过期并完成多节点核查后，可标记“已过期未确认，预留款已释放”。TCL 结束原任务，保留原 intent、哈希与地址去重，不记为到账成功或链上执行失败，不自动重发。
- 恢复独立本地前，先在平台切回普通租赁并完成原交易核查，再在 TCL 点击“恢复独立本地模式”。服务端确认安全解绑、客户端收齐原订单终态后才清除绑定；解绑响应丢失可再次操作。
- 升级保留配置、钱包、去重记录、队列、扫描进度及平台订单，重新打开保持暂停。TRC10 钱包池继续独立本地使用；当前平台无感模式限 TRC20。

- 窗口不带浏览器工具栏和自动翻译入口，页面明确禁止翻译。
- 标题栏改为统一的白色与淡紫灰配色；保留 Windows 原生窗口按钮和拖动区域，正文滚动条从标题栏下方开始。
- 最小化继续运行；关闭窗口会暂停新投放、保存进度并退出。桌面意外退出时，后台也停止；界面异常恢复前先暂停投放。
- 保留旧版启动脚本和 EXE 入口、更新签名、ZIP 目录布局，支持旧版迁移。更新进程等待窗口及后台退出后安装，新版默认暂停。
- 自带固定版本 Electron 45.3.3，运行包经官方校验值验证；加入桌面运行环境检查和修复。
- 保留本地 SQLite 数据、地址去重、待确认交易和加密钱包库；不改变投放数量、资源门槛或重试规则。
- 大更新包的下载等待上限延长至 10 分钟。1.0.3～1.0.5 如已安装但 EXE 被 Windows 拦截，请双击同目录“一键启动.cmd”；旧版下载超时可用完整 ZIP 保留 data 手动迁移。
- 修正未保存确认框长时间停留造成的无响应误报，以及钱包池侧栏文字换行。
- 退出时清理桌面预连接；更新期间在后台保存完成后完整结束旧桌面进程，避免新旧进程互相等待导致安装超时。

- 保留旧版记录、去重、签名交易及重试状态；数据库结构变更前自动备份。无新增第三方依赖。

真实 Token 尚未提供，本版完成隔离签名、模拟节点、迁移和界面验收，尚未执行真实激活、分币或投放。

# 1.0.9 更新说明

修复单笔投放异常和「需核查」记录卡住整个工具的问题。

- 首次失败后最多补试 3 次（共 4 次），先核查结果，再复用同一签名交易；确认失败或核实过期且未上链后才允许重建。次数跨重启保存，成功一笔清零连续失败计数。
- 单笔用完重试后继续其他地址，连续 3 笔仍未成功才暂停。能量或余额不足、交易参数或到账核对异常仍立即保护暂停。
- 待核查交易后台持续核查，不阻止重新启动或暂停后的软件升级。暂停时不补发；更新后保持暂停。节点错误码、原因、重试次数和历次哈希可查。
- 扫描临时异常保留原高度重试，不再因连续 5 次读取失败停止；逐高度补扫，仍保留高度倒退和积压上限保护。
- 失败尝试消耗保留并计入统计，成功数量只计一次；缺失成本继续延后补齐。
- 新增 `scripts/升级旧版.cmd`：从新包双击运行，输入旧版文件夹路径，自动保留 data、备份并直升最新。兼容 1.0.3 按钮被锁的情况。

旧版仅有哈希而无签名/有效期的记录，需按最长 24 小时有效期核实安全过期后再重建补发；期间不影响新地址投放或升级。新记录可直接复用原签名重试。

# 1.0.5 更新说明

新增「投放统计」，入口位于左侧「投放总览」下面。默认近 15 天（包含今天），只列有数据的日期；可选近 30 天、近 90 天、全部或自定义日期。每页最多 15 个有数据的日期，顶部卡片和表尾合计覆盖整个所选范围，CSV 导出也包含所有分页。

# 1.0.3 更新说明

修复工具被其他窗口盖住或最小化时，页面定时器降频导致 45 秒心跳超时并误暂停的问题。现在后台识别该工具专属浏览器配置对应的原生窗口，最小化、遮挡、切换软件不会被当作关闭；真实关闭窗口后约 10～20 秒暂停。能量不足、余额不足、广播未知和交易失败保护保持生效。

新增“使用与迁移 → 软件更新”：从 GitHub Releases 检查版本、显示说明、下载并安装。发布包必须通过内置公钥签名和 SHA-256 校验；只替换白名单程序文件，保留 data。更新前自动备份，安装检查失败恢复旧文件，重新打开后保持暂停。初次使用在线更新须先安装本版本；发布仓库无可用版本或网络失败时会提示。

| 文件 | 内容与原因 |

# 1.0.2 更新说明

本次让地址上限和重新启动策略更容易找到，并把投放交易的执行成功与最终确认分开处理，缩短逐笔等待时间。

## 使用变化

- “投放参数”最顶部新增“本次投放与重新启动”，总览同步显示三个策略。
- 地址上限默认 **无上限**；勾选“自定义上限”后可填写 1～100000，达到数量自动暂停，每次启动重新计数。
- 重新启动默认从 **最新已确认区块** 开始；可切换为接着上次进度补扫。
- 旧等待地址默认 **不补发**；可切换为补发等待队列。已广播的交易始终继续核查原哈希，不会重新发送。
- 上一笔经普通节点执行 SUCCESS 并核对 Transfer 金额后，按投放间隔继续下一笔；后台自动补查最终确认。记录区分“执行成功 · 待最终确认”和“已最终确认到账”。
- 合约信息缓存，每笔保留实时余额与能量检查；新地址入队时及时唤醒空闲发送器，避免额外等待一次轮询。

轮询 3 秒本身不会漏掉中间区块，扫描会按高度逐个补齐，读取失败不推进进度。节点限流或积压超限会暂停提示。默认最新启动会主动跳过停机区块；需要补齐时选“接着上次区块扫描”。

旧未发送队列仅在下次成功点击开始时按策略处理。默认略过会保留历史记录和同一触发交易去重；对应地址以后出现新的达标交易仍可命中。预检或资源检查失败不会提前略过队列。补发前核对全部旧队列的节点、合约和数量，防止按变更后的配置误发。

# 1.0.1 更新说明

## 使用位置

- 双击 `TCL广告投放工具.exe` 或 `TCL.exe` 启动，默认暂停。
- 左下角：“开发者联系方式：”＋ Telegram 图标＋ [@tangyuan0936](https://t.me/tangyuan0936)。
