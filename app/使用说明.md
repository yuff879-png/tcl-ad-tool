# TCL 广告投放工作台 1.3.10

双击 **一键启动.cmd** 打开 Electron 独立桌面窗口，使用自带的 Node.js 和 Electron 运行环境，无需安装 Edge 或 Chrome。也保留 TCL广告投放工具.exe（或 TCL.exe）启动入口。程序默认暂停，不会自动投放，支持 Windows 10/11 x64。

## 1.3.10 手动批量投放

左侧「批量投放」可直接粘贴收款地址，或导入 UTF-8 TXT / 单列 CSV。每行一个地址，也支持空格或逗号分隔；单批最多 10,000 条，文件不超过 1 MB。代币、每地址数量、发送钱包和间隔使用已保存的投放参数，TRC20 与 TRC10 仍二选一运行。

1. 填写名单，选择本批「去重发送」或「历史地址也发送」，再点击「预览并确认投放」。预览显示有效地址、总量、原发送间隔以及被排除的地址；这一步不会发送代币。
2. 正式投放需核对并勾选确认。正在运行时加入优先队列；暂停时，确认后按所选模式启动扫描并处理本批。运行期间沿用当前正式或模拟模式。
3. 当前正在处理的一笔正常完成后，先按名单顺序处理手动批次。多个批次按添加顺序排队。正常扫描继续，命中的地址进入普通队列，手动批次处理后接续发送。
4. 在批次记录查看进度或进入对应投放记录。可「取消剩余」，只取消该批尚未开始的地址；正在处理或已广播的交易继续核查，历史和去重保留。

**发送间隔完全沿用原设置，仍由同一个发送任务逐笔处理。** 加入名单不会缩短上一笔结束后的等待，不增加并发；最终确认和消耗统计继续在后台补齐。原余额、能量、TRC10 免费带宽、平台预算、连续失败及本次地址数上限继续生效，等待资源时仍需等资源达标。

无效、名单重复、黑名单和自身钱包地址会被排除。默认「去重发送」跳过当前代币下已有去重记录的地址；「历史地址也发送」允许向已完成投放的地址再发一次，并保留原历史和去重。正在排队、发送、待确认、结果未知以及仍需核查的旧交易不能绕过检查。扫描队列中尚未开始的相同地址会提升为手动优先，保留原触发交易，避免投两次。正式与模拟分别去重，确认时会再次校验，避免预览期间状态变化造成重复发送。

手动等待队列最多 10,000 个地址（含暂停保留），与扫描队列容量分别计算。TRC10 扫描等待有效期不用于手动名单。

**主投放任务暂停后，可以手动续发本批剩余名单。** 软件重启、能量不足停止或达到本次上限后，批次记录显示「已暂停 · 等待手动续发」。点击「继续发送」，核对剩余数量、代币、每地址数量和间隔后确认。主任务已暂停时会先重新预检并启动扫描，主任务正在运行时直接恢复本批优先队列。保留原记录 ID 和已完成进度，不会重新发送本批已经完成的地址，也不会自动恢复其他暂停批次。

代币、每地址数量、节点或运行模式与原批次不同时会提示恢复原设置。资源不足、钱包池未解锁等条件未通过时保持暂停，名单不丢失。预览关闭或重复点击不会多建批次；发送频率继续使用当前已保存的间隔。

普通扫描的重启起点和旧队列处理继续按原设置，自动能量恢复从新区块开始。仅启动主任务或自动恢复不会自动续发手动批次，需在批次记录单独确认。此前已被旧版本略过或用户取消的名单不属于「剩余未发送」，需重新导入并预览。

## 1.3.8 平台运行状态与远程启动

将已绑定平台的 TCL 更新到 1.3.8 并保持程序打开、联网，在平台“地址与策略”可查看设备是否在线、实际运行模式、最近成功扫描时间、扫描高度及异常原因。状态约每 5 秒同步，超过 30 秒未收到运行报告时显示离线或状态过期；程序心跳与成功扫描分别记录。升级前没有扫描时间记录时显示尚未扫描，不能用最近联系时间替代。

在平台点击“远程启动正式投放”，核对钱包、代币、单笔数量、间隔、数量上限和重启处理方式后确认。它使用 TCL 已保存的参数，可能发送真实代币；本机仍执行与原正式启动相同的预检和资源检查，不修改参数或绕过地址、余额、能量、预算及去重保护。有待确认交易、自动恢复任务或本机操作未完成时，先按提示在 TCL 处理。

确认请求只对当前 TCL 进程、当前配置及能量策略有效，60 秒内未能完成启动将失效。程序关闭或重启、参数变化、本机暂停和退出都不会在之后自动补执行旧请求。重复领取和领取响应丢失也不会重复启动。网页“已启动”表示 TCL 已完成预检并进入正式运行，投放交易结果仍以“投放记录”和链上确认分别为准。

本功能不能远程打开已经退出的 TCL 或唤醒电脑。旧版本仍可保持原能量联动，运行详情与远程启动需更新后使用。本机“暂停”和退出继续优先生效；首次启动或升级后默认暂停。

## 1.3.7 平台投放统计同步

绑定平台后，普通投放和无感投放的最终成功交易会自动补报。已有免费资源的无感交易也包含在内。平台按交易哈希去重，并独立核验链上结果，按交易所在区块的日期统计；租能量成功不等于投放成功。

完整的本机历史成功记录可自动补报，缺少交易哈希、原钱包、原始数量或链上日期的记录不冒充成功统计。断网和平台异常不会阻塞投放，本机队列在下次启动或恢复连接后继续。平台连接区显示同步状态；“平台已接收”表示已进入平台核验队列。

TRC10 钱包池广告记录首次补报需解锁原钱包库以证明钱包归属。证明只用于当前平台和设备的统计登记，不会转账，也不上传私钥或交易签名。钱包池激活、补币和模拟投放不计入。TRC10 继续使用本地免费带宽路径。独立本地模式只保留本机数据，重新绑定后可补报可验证的历史记录。

## 桌面窗口与升级

- 界面使用独立的 Electron 窗口，投放引擎运行在独立 Node.js 进程中；本版沿用原投放规则和数据库。
- 浅色标题栏与页面统一；拖动顶部空白处移动窗口，双击空白处切换最大化/还原，右上角保留 Windows 原生最小化、最大化及关闭按钮。
- 最小化、切换其他软件会继续运行。关闭最后一个窗口会停止开始新投放，保存处理中的交易后退出；下次打开继续核查已广播交易。
- 桌面进程意外关闭时，后台会通过进程通信断开事件停止投放并退出。界面渲染异常时先请求暂停，再提供重新打开界面的选择；不会自动恢复正式投放。
- 下载更新完成后由用户确认安装，退出窗口和后台后再替换文件。原 data、加密钱包库、地址去重及待确认交易保留，新版仍默认暂停。
- 1.3.4 延长启动等待并核对实际运行版本；重复打开会等待正在启动、退出或更新的过程，再聚焦同一窗口。升级后先等待自动打开，在更新页核对版本；旧更新器第一次安装本版时仍受旧等待时间限制，若窗口最终未打开，可使用“一键启动.cmd”。
- 弹窗右上角“关闭 ×”始终可见，长内容可单独滚动；点击外侧遮罩或按 Escape 也可关闭。核查或提交处理中暂时不能关闭；需要中止尚未执行的后续步骤时使用“停止后续操作”，已提交交易仍按原哈希核查。
- 旧版远程迁移沿用原更新通道、签名和启动入口；不需要逐个安装中间版本。正式发布前可先使用独立测试版目录，不要让两个程序同时使用同一份 data。
- 修复运行环境会从官方来源下载并核验固定版本 Electron，首次解压完整包无需另行安装。

保留 TRC10 免费带宽钱包池；TRC20 与 TRC10 二选一运行，钱包池在“投放钱包池”页面管理。1.3.0 新增可选的 TRC20 能量平台连接。参数按投放策略、钱包与节点、代币与触发、资源与节奏分组，点击「保存全部设置」可统一保存所有分组。

## TRC10 免费带宽投放

工具不提供代币发行。已有 TRC10 Token ID 后，在“投放参数”选择 TRC10，填写 Token ID、每地址数量、免费带宽余量、等待队列有效期与容量。原 TRC20 参数保留；切换类型需暂停并确认。切换类型或代币后，旧的已广播交易只核查，不再自动补发。

1. 在“投放钱包池”创建加密钱包库，设置至少 10 字符的密码。密码丢失无法恢复私钥；每次重新打开都需解锁。
2. 打开“批量准备”，自定义本次生成数量（1～100000）。生成只在本地进行，不上链、不花费费用。后续可随时再新增一批。
3. 创建完整备份，输入密码验证备份。生成新钱包会使旧备份验证失效，必须再次备份验证。完整备份应另存到其他安全位置。
4. 在参数中配置独立的准备资金钱包私钥，资金钱包需持有待分发的 TRC10 和足够 TRX。日常投放不使用该资金钱包。
5. 选择激活并分币，填写实际处理数量、每钱包分币量、TRX 总预算及每组待确认笔数。可以只激活部分；生成批次 ID 可在钱包列表复制，用于限定本批范围。先预检，核对弹窗后由用户确认真实链上操作。
6. 激活与分币合并为一笔 TRC10 转入；费用由资金钱包承担。未确认费用和代币会预留，超过预算或余额不足暂停。已广播交易只查原哈希，不自动重复转入；确定过期未上链的目标可重新规划。准备中可以暂停，稍后在“准备批次”继续。
7. 最终确认成功的钱包自动启用。到总览先模拟，再手动开启正式投放。准备完成不会自动开始投放。代币不足可通过“向已激活钱包补充代币”处理；补币也是资金钱包的准备费用，不属于免费日常投放。

**免费模式条件：**发送钱包已激活、标准单签、TRX 余额为 0、没有质押或受托带宽、代币余额充足、免费带宽覆盖实际签名交易大小与余量。存在发行者带宽补贴的代币会被拒绝。未激活的收款地址跳过，避免由投放子钱包承担激活费用。请勿向子钱包充值 TRX 或委托带宽。

282 带宽是参考值。程序计算签名交易序列化大小，加入链上结果开销，并在广播前复核资源。按 600 免费带宽与约 282/笔，参考容量约为已激活启用钱包数 × 2；真实可发送数量取决于交易大小、余额和免费资源。免费带宽约 24 小时滚动恢复，不在每天零点重置。一个钱包不足则轮换，全部不足时保持监听并等待；资源不足不计入投放失败。

等待地址默认有效 30 分钟、最多 10000 条，可自行调整。队列满时保留扫描进度，超时未发送地址略过。发送结果暂不明确时锁定该钱包与原哈希，其他钱包继续；最多首次加 3 次补试，只有原交易最终失败或确认过期未上链才允许安全重建。

投放统计在 TRC10 下显示带宽、实际 TRX 手续费，不套用能量统计；仍默认当前代币、近 15 天、北京时间，可切换 UTC。激活与补币费用在“准备批次”独立展示。最终确认和统计在后台补齐，不阻塞下一笔正常投放。

## TRC10 换机与备份

停止任务并退出程序后，复制整个工具文件夹即可；使用干净新版时，先退出两边程序，再将原版的完整 data 文件夹复制到新版。必须一起保留 config.json、records.sqlite、pool-vault.json，以及原有其他 data 文件，不能只复制数据库或只复制钱包库。重新打开后保持暂停，输入原钱包库密码解锁，重新备份验证再操作。

子钱包私钥加密存于 pool-vault.json；资金钱包私钥和原 TRC20/API 配置延续本机 config.json 存储方式，完整备份包含这些配置，请勿公开分享 data。对外便携包不含任何个人数据或发布签名私钥。

## TRC20 日常使用

1. 在“投放参数”填写钱包私钥、广告代币合约、投放数量、转账门槛和资源条件；在“地址管理”填写监听地址与黑名单。
2. 保存设置，点击“只读预检”。读取已确认区块、代币精度、余额与能量，不签名、不广播。
3. 先启动“模拟监听”，查看实际命中。模拟记录不占用正式投放的去重记录。
4. 切换“正式投放”，核对确认框中的完整钱包、合约、精度、数量及本次上限，勾选后启动。
5. 暂停后等待状态变为“已暂停”。已广播交易继续核查，不会撤回。异常时根据日志和交易哈希处理。

界面每 2.5 秒刷新本地状态。切换软件、窗口遮挡、最小化或锁屏不影响后台投放；窗口仍需保持打开。关闭窗口后直接通知后台暂停并保存进度，处理中的交易状态保存后退出；点击“退出程序”也会有序退出。电脑睡眠期间无法监听。能量、余额和交易异常保护照常生效。

## 平台连接与无感能量（1.3.1）

**不绑定平台即可独立使用。** 新安装和旧配置升级均默认保留本地模式；原查询节点、能量门槛、钱包和投放规则继续有效。平台连接目前只适用于 TRC20，TRC10 钱包池继续使用独立本地模式。

### 绑定当前钱包

1. 暂停 TCL，在“投放参数”保存 TRC20 钱包、广告代币合约与投放数量。本地普通待核查记录不再阻止首次绑定；切换发送模式时仍会等待旧交易安全处理。
2. 登录能量平台客户后台，找到同一个发送钱包地址，生成一次性设备绑定码。
3. 打开 TCL“投放参数”顶部的“能量平台连接”，填写客户平台的 HTTPS 域名（不带路径），粘贴绑定码，点击“绑定当前钱包”。
4. TCL 只在本机签署绑定证明，并保存该钱包专属的设备凭据。成功后显示钱包、当前模式、售价及策略版本；任务仍保持暂停。
5. 在平台地址页面选择“普通租赁”或“无感能量”。看到 TCL 显示已生效后，再按原流程预检、确认并手动开始正式投放。

平台地址填写客户后台入口，不是供应商节点地址。绑定码只用于一次配对；私钥无需填写到平台。绑定后不能直接换发送钱包或切到 TRC10，须先完成安全断开。

### 连接状态与运行方式

| 状态 | 广播与资源要求 |
|---|---|
| 独立本地 | 无需平台连接，使用原本地查询和广播设置、原资源门槛 |
| 已绑定：普通租赁 | 由平台同步策略，TCL 仍按原节点本地广播，保留最低能量及 TRX 门槛 |
| 已绑定：无感能量 | TCL 本地签名后发给平台；已有资源足够时由平台普通直发，否则按平台条件处理补能 |

无感模式只改变签名交易的广播入口，查询 RPC 不变。扫描、余额查询、构造交易与回执核查继续走原 RPC，不把日常查询集中到供应商节点。原“最低剩余能量”在无感模式下暂不拦截；平台判断的是资源能否完成下一笔，不要求钱包先用到 0。平台继续使用地址原有的 TRX 停止线、恢复线、自动恢复开关，并检查带宽、代币余额及合约限制等条件，费用上限也不会超过本地保存的上限。

运行中切换模式会在交易边界生效。等待原交易或平台订单结束时暂停新发送，保留扫描进度、等待地址和本次成功数量，不重置本次上限。准入容量不足时先等待再签名；等待不计失败。签名提交阶段只有下述明确容量拒绝例外允许同一签名重交平台。队列满时保留当前扫描高度，之后继续补扫。该切换不调用旧的“从最新区块重启”自动恢复流程；手动暂停的任务不会被远程模式切换启动。

### TRX 停止与恢复保护

无感模式只忽略固定最低能量，继续与普通租赁共用平台地址的 TRX 保护规则。例如停止线 15 / 恢复线 20 TRX：平台首次有效读数低于 15 即锁定暂停，新发送停止；回升至 17 不会恢复。开启自动恢复时，需要连续两次有效采样达到 20 才解除；关闭时保持等待，需要在平台地址页面手动启用。已有资源免费直发同样受这项保护。

TCL 不另设 0.1 TRX 门槛，也不凭本机一次余额回升自行解除平台锁定。已运行任务保持扫描、等待队列和本次计数，仅暂停新发送；平台恢复后该任务继续。用户主动点过暂停或已退出程序，则仍需手动启动，不受平台恢复指令自动启动。

### 服务费与异常结果

已有资源普通直发的无感服务费为 0。无感补能路线在平台核实原交易固化成功、准确到账及完整能量回执后，按该笔接单时的售价收一次服务费；例如接单售价 0.95 TRX 时，后续调价不会追改该笔。等待确认期间为预留，未知结果继续核对；供应商成本记录与客户固定服务费分别处理。钱包的链上手续费和平台服务费是两项，记录、统计及 CSV 分开显示。

向平台提交签名交易前，TCL 已持久保存原 intent、交易哈希及提交标记。响应丢失、断网、程序退出或重启后，只查这个原订单，不重新签名、不重新提交、不回退到本地或其他节点广播，也不套用本地最多 4 次补试。已广播的原交易过期本身也不能作为再次购买或重发的理由。等待签名前的准入可以按平台许可重新取得；已经可能提交且结果未知的交易始终只查原单。

只有平台返回 HTTP 429，且明确包含 code=energy_capacity_wait 与 broadcast_started=false 时，才允许保持同一 intent、同一准入许可和同一签名交易，等待 1 秒加随机抖动后再次提交平台网关；总共最多 12 次提交（含首次）。每次等待后复核任务仍在运行、策略及版本未变化、准入许可和签名交易仍有效。普通 429（包括代理限流）、超时、断网及其他未知回复均不适用，一律只查询原订单；即使先收到安全容量拒绝，之后一次提交超时，也立即停止重交。这个例外只重交本平台网关，TCL 不直接重试 CatFee，不重签或生成新 intent。

平台在广播前新鲜余额检查中触发 TRX 保护时，只有 HTTP 409 energy_trx_paused、broadcast_started=false 且 intent/准入许可均匹配，才证明本签名从未转发。服务端取消旧许可，TCL 将原任务保留在等待队列并保存旧签名审计；平台按恢复规则解除后，以同一 intent 取得新许可并签名，绝不重播旧签名或旧许可。其他 409、超时或未知回复仍只查原单。

长期未知的原交易可由平台管理员在核实过期并完成多节点核查后关闭，显示“已过期未确认，预留款已释放”。这不代表到账成功或链上执行失败；TCL 结束原任务，保留原 intent、哈希与地址去重，不自动生成新 intent 或重播。

平台策略失效、地址暂停或凭据撤销时停止新发送；原交易仍按保留的数据核查。界面顶部显示模式、等待原因和异常状态。需要人工核对时保留原单处理，不清空历史来跳过保护。

### 安全恢复独立本地

1. 在平台将该地址切回普通租赁，等待模式生效及原订单完成；在 TCL 暂停任务。
2. 等待本机原交易的链上核查结束，点击“投放参数 → 能量平台连接 → 恢复独立本地模式”。
3. 平台核实该地址已处于普通模式、没有在途服务且没有替代活动设备；TCL 收齐原订单最终费用后，才清除本机设备凭据。
4. 完成后使用原查询节点、资源门槛和配置，重新预检并手动启动。

解绑响应丢失可再次点击恢复；已经在网页解除绑定时，也通过同一入口核对收尾。不能通过断开连接跳过未知交易或费用。升级及换电脑需完整保留 data，其中包含配置、设备凭据、原签名、平台订单、队列和扫描进度；升级后保持暂停，不自动投放。

## 能量恢复后自动继续（独立本地 TRC20）

在“投放参数 → 资源与节奏”开启“能量恢复后自动继续”并保存，然后正常预检、确认启动正式投放。开关默认关闭，旧配置升级后也保持关闭。

只有已启动的正式投放因为钱包能量低于“最低剩余能量”门槛停止，才进入等待；按“能量检查间隔”读取该钱包的能量，默认 120 秒，可设置 10～86400 秒的整数。达到门槛后重新检查 TRX、代币余额及节点，预检通过才自动继续。检查由后台进程执行，最小化不影响计时；电脑须保持开机、联网且程序未退出。暂时无法查询节点时，等待设定间隔后再次尝试。

自动恢复固定从恢复当时最新已确认区块开始，只处理之后的新触发交易。中断前未发送的旧队列略过；旧已签名或已广播交易停止补发，只在后台核查链上结果。此策略适用于自动恢复，手动启动仍使用下方的扫描起点与旧队列设置。自动恢复期间本次成功数量及地址数上限继续累计，不会重置额度。

页面顶部显示等待状态和下一次检查倒计时，点击“取消自动恢复”即可保持暂停，随后可以修改开关或参数。手动暂停、修改设置、关闭程序、安装更新、其他错误停止均不会自动重启；重新打开程序也保持暂停。此功能不适用于 TRC10 或模拟监听，也不会把链上 OUT_OF_ENERGY、单笔能量费上限不足、TRX 不足等所有失败都当成能量门槛不足。

## 本次投放与重新启动

在“投放参数 → 投放策略”集中设置三个策略，投放总览启动卡片下方同步显示：

- **本次地址上限：默认无上限。** 需要限制时勾选“自定义上限”，填写 1～100000 的整数；达到上限自动暂停。每次手动开始重新计数，补发旧等待队列也计入本次上限。
- **重新启动扫描：默认最新区块。** 以实际点击开始时最新已确认区块为起点，跳过停机期间区块。选择“接着上次区块扫描”则从保存的进度逐个补扫，超过补扫上限会提示停止。
- **中断前未发送地址：默认不补发。** 下次成功启动时把当前模式旧等待队列标记为“重启已略过”，保留历史明细；这些地址以后出现新的达标交易时仍可命中。同一笔旧触发交易不会重放。选择“补发等待队列”会保留旧队列，按原合约和原数量发送。

扫描起点与旧等待队列是两个独立选项。例如“最新区块 + 补发等待队列”会跳过离线区块，但补发已经发现、尚未发送的地址。资源不足、预检失败或续扫积压超限时，不会提前丢弃等待队列。原队列的节点、合约、数量与当前设置不一致时，补发会被阻止。

“不补发”仅适用于尚未广播的等待记录。已广播交易始终保留原交易哈希继续核查，不会因为重新启动而再次发送。

## 发送速度与最终确认

以下速度与补试规则适用于本地广播。无感模式按平台原订单与链上最终确认串行处理，详见“平台连接与无感能量”。

上一笔经普通节点查询到执行 SUCCESS，且代币、投放钱包、收款地址和 Transfer 数量均核对通过后，等待“投放间隔”即可发送下一笔，不再等待最终区块确认。总览与记录页分别显示“执行成功 · 待最终确认”和“已最终确认到账”。后台每 5 秒分批核查最终确认，暂停后也继续；退出程序后，下次打开会接着查。

广播被接受本身还不算执行成功。首次尝试失败后，最多再补试 3 次（合计最多 4 次），先查结果，再复用有效期内的原签名交易和哈希；只有最终确认失败，或确认链超过有效期且交易/回执均查不到时，才重建交易。单笔重试用完保留记录并继续下一个地址，连续 3 笔重试后仍未成功才暂停，成功一笔清零。次数持久保存，暂停、重启、升级不会重置次数。每笔仍检查能量、TRX 和代币余额；资源不足、交易参数或到账核对异常立即保护暂停。

## 3 秒轮询会不会漏块

不会仅因为设为 3 秒而漏掉中间区块。程序按保存高度逐个扫描，例如从 100 跳到 103，会依次处理 101、102、103；读取失败不会推进该区块的进度。节点限流可能造成延迟和积压，连续失败或积压超限会暂停提示，不会自动跳块。

默认“从最新区块重新开始”会主动跳过停机期间区块，这是启动策略。想补齐停机区块，请在启动前选择“接着上次区块扫描”。监听仍使用已确认区块，通常落后链头几十秒；此延迟与投放交易的后台最终确认是两件事。

## 清空已投放地址

在“地址管理”名单编辑区下方找到“已投放地址去重”。先暂停任务，再点击“清空已投放地址”，核对数量、勾选说明后点击“备份并清空”。正式地址包括旧版历史地址和已确认到账的地址；模拟命中地址可用旁边的按钮单独清空。

清空前自动备份至 `data/backups/清空地址前-*`。完成后，这些地址出现**新的达标转账**时可以再次命中。历史明细、投放交易哈希、累计成功数量和扫描进度保留，不会重扫以前的交易。等待、失败、取消、普通跳过的地址仍保留去重；“重启已略过”的未发送地址允许以后新的交易再次触发。有执行成功待最终确认或结果未知的交易时，须先核查完成。

## 规则与旧版差异

- 监听地址作为转出方或收款方，转账达到门槛时，始终向原交易的**收款地址**投放。
- 支持普通 TRX 转账和配置 USDT 合约的直接 `transfer(address,uint256)`；不解析 transferFrom、内部转账或其他代币。
- 扫描已确认区块，通常比最新区块滞后约几十秒；USDT 触发还须核对链上 Transfer 事件，避免失败转账触发。
- 黑名单、自己钱包、已投放地址、旧版历史地址、同模式队列中已有地址均跳过。地址区分大小写。
- 按链上精度计算金额，使用整数运算；不再把所有代币都当成 6 位。原包 x9.bet 合约实际为 **18 位**，填写 168 表示 168 个 x9.bet，正式启动前请特别核对。
- 正式投放的“已确认到账”需匹配交易回执和准确的代币、发件钱包、收件地址、数量。广播被接受不等于到账。
- 本地广播前保存签名交易、哈希与尝试次数。未知结果先核查，再按上述额度重试；待确认与失败记录保留地址去重和历次交易哈希。暂停时只核查，不签名、不补发；手动启动正式投放后才继续有剩余额度的重试。旧记录须匹配当前钱包、合约、数量和节点才可补试。
- 本地广播串行发送，上一笔普通节点执行成功并核对 Transfer 后按间隔继续，最终确认后台补查；无感模式等待原订单及最终回执。每次手动启动重新计算本次地址上限，默认无上限。
- 默认从最新已确认区块开始、不补发旧等待队列；续扫与补发可在参数页分别选择。续扫长时间离线超过补扫上限时会提示停止。单独手动重设起点不会直接清空已入队记录。
- 旧包的 Telegram 独立告警脚本不自动启动。本版提供钱包资源展示与本地日志，没有向 Telegram 发消息。

## 费用与资源

独立本地模式及已绑定平台的普通模式沿用原最低剩余能量。每次正式投放前检查能量、TRX 和代币余额，并要求 TRX 覆盖“能量费上限 + 保留余额”，有能量也执行此条件。单笔能量费上限是交易 `fee_limit`，不是固定手续费；带宽可能另扣，保留余额并非绝对最终余额保证。

无感模式跳过上述固定最低能量和 TRX 相加门槛，使用平台逐笔资源判断，并继续执行地址共用的 TRX 停止线、恢复线及自动恢复开关；代币余额仍须充足。签名时采用本地与平台两者中较小的费用上限，不修改保存的本地配置。平台无感服务费与钱包实际链上费用分开记录，实际状态以平台订单和链上回执为准。

TronGrid Key 与 TronScan Key 不通用。原包只有 TronScan Key，新版 TronGrid Key 留空，需要时在界面填写。无 Key 的公共请求可能被限流；临时读取失败保留扫描进度并退避重试，不再因连续 5 次读取失败直接暂停；节点高度倒退或积压超过补扫上限仍暂停提示。

## 投放统计

左侧「投放总览」下面的「投放统计」默认展示近 15 天（包含今天），无数据日期不占行。选择更长日期范围后，每页最多 15 个有数据的日期，可翻页。顶部及表尾合计、导出 CSV 都按整个所选范围计算，不只是当前页。

日期取投放交易的链上时间，默认北京时间 UTC+8，可切换 UTC；切换时重新按日归档。默认查看投放参数中当前配置的广告代币，修改投放合约后会自动跟随，也可手动选择其他历史代币或全部代币。未设置当前合约时会提示，不会把所有历史代币混入默认统计。只统计正式成功投放的笔数与数量，模拟、跳过、取消不计入；不同代币的数量分别显示。

能量取最终回执的总能量消耗，TRX 取实际链上手续费（含带宽等链上费用），不使用余额差或设置中的单笔上限。上链失败或异常交易消耗也计入，并在对应日期注明。平台服务费另外显示，不与链上 TRX 相加混写；尚未结算的服务费显示待核对。平台服务费晚到后归入原交易的链上日期，只计一次；其他外部租能量付款不在本表内。

发送不等待统计：新交易在现有后台最终确认时记录消耗；缺失统计的旧交易仅在暂停时分批补查，失败会延后重试。部分消耗显示「待补齐」，未最终确认和日期缺失的交易在提示栏单独列出（这些提示笔数不限所选日期）。补齐后计入交易发生当天。仅迁入的旧地址名单缺少逐笔明细，无法还原日报。清空已投放地址不删除统计；备份数据库会一起保存统计。

## 在线更新

打开程序后会自动检查更新，之后每 6 小时检查一次；网络失败约 15 分钟后重试，不影响投放。发现新版时，左下角版本区域会显示“发现 v<版本> · 点击更新”，点击即定位到更新卡片。窄窗口下显示带提示点的向上箭头。

在“使用与迁移 → 软件更新”或左侧更新卡片手动检查。有新版本时点击“下载新版本”，可查看进度；下载校验完成后再确认安装。运行中的投放或钱包准备会先暂停，已广播记录保留。程序下载 GitHub Releases 发布包、校验发布签名与 SHA-256，退出旧进程后备份数据库、配置、加密钱包库及被替换的程序文件。新版本启动时自动关闭同一工具目录遗留的旧窗口，再打开新界面并保持暂停；普通浏览器和其他工具目录的窗口不受影响。如果旧窗口因系统限制或关闭确认暂时无法关闭，会提示手动处理。

钱包、参数、去重历史与扫描进度都留在本机。下载或校验失败不修改旧程序；安装检查失败恢复旧程序文件，失败详情显示在更新卡片。安装不自动开始投放。有待核查记录也可升级，交易哈希、重试次数和去重记录会保留；升级后保持暂停并恢复只读核查。

发布仓库：https://github.com/yuff879-png/tcl-ad-tool 。网络不能访问 GitHub 时会提示失败，可稍后重试或在发布页下载便携包。没有发布版本时返回未找到更新的提示，不代表本机启动故障。

## 旧版升级按钮不可点击（包括 1.0.3）

旧版自身的限制不会随新版发布自动消失，请执行一次原地升级：

1. 在旧版暂停投放，点击「使用与迁移 → 创建备份」保留一份副本，再点击「退出程序」。
2. 从 GitHub 最新发布页下载 ZIP，完整解压到一个新文件夹，不要在压缩包内运行。
3. 打开新包的 `scripts` 文件夹，双击 `升级旧版.cmd`。
4. 粘贴原 1.0.3 工具文件夹的完整路径（不是 data 子目录，也不是新解压目录），回车。
5. 工具会下载最新签名包、自动备份和替换程序文件，原 data 留在原处。完成后自动打开新版；没自动打开时双击原文件夹的「一键启动.cmd」。确认左下角版本，再手动启动投放。

此入口可跨版本直升最新；无需逐版安装，也不要清空或删除「需核查」记录来解锁更新。GitHub 不可访问时会报告失败，保留旧程序。

1.0.3 等旧版只保存哈希，缺少原始签名和有效期：首次导入按记录时间加 TRON 最长 24 小时有效期，再等待确认链越过安全余量并核对不存在，才能重建补发。期间继续新投放；确认已到账则不补发。新版原生记录可直接按原签名有限重试。

## 换电脑

1. 暂停并退出程序；待核查交易随完整 data 一起迁移。
2. **复制整个文件夹**到另一台 Windows 10/11 x64 电脑，双击“一键启动.cmd”。不要只复制 EXE，也不要从压缩包内部直接运行。
3. 保留 `data`：其中有配置、私钥、历史去重数据、扫描进度和队列。旧电脑与新电脑不要同时运行同一钱包的投放工具。
4. `runtime` 已带 Node.js 24.15.0 和 npm；`node_modules` 已带全部运行依赖。无需系统 Node、Python、Visual Studio、管理员权限。
5. 正常打开界面不需要下载依赖。链上读取与投放需要联网；损坏时运行“修复运行环境.cmd”，从官方 Node / npm 下载。修复不会改配置和业务数据库，执行修复前先退出工具。

给其他人使用请发 `TCL广告投放工具_便携版_1.3.7.zip`。此干净包不包含个人钱包私钥和历史记录，需要首次配置。自己的换机请完整复制已配置的文件夹。

## API 额度与公共节点（1.0.10）

- 配置的 TronGrid 主网 API Key 遇到 429、频率限制或用量耗尽时，自动切换 `https://api.trongrid.io` 的匿名公共接口，不清空保存的 Key。当前进程继续用公共接口，重开程序后优先使用已配置的 Key。
- 未配置 Key 时，本来就在使用公共接口。公共接口也可能限流；此时至少冷却 60 秒，并遵守节点返回的更长 Retry-After，运行中的任务恢复后自动继续。公共节点请求会适当放慢，避免持续撞限流。
- 限流不消耗投放尝试次数，不累计连续失败。已接受的广播仍算一次正常尝试；其后的查询限流只等结果，不会据此重发或生成新交易。明确被限流拒绝的广播退回本次额度，保留原签名及哈希。
- 扫描、预检、投放、后台最终确认和统计补查共用节点状态。等待时保留区块进度和队列；限流造成的运行中积压会继续逐块补扫。顶部会显示公共节点或限流等待，并展示提示。
- 暂停时仍仅做后台核查，不自动开始投放；可以正常退出或安装更新。能量不足、余额不足、交易核对异常的保护不变。
- 自定义 RPC 可能属于其他网络，仅在原节点冷却，不自动把交易发到主网。预检遇到所有节点限流时会提示等待，恢复后可重新点击预检。

## 处理历史待核查记录（1.3.1）

先暂停任务，再进入“投放记录”，找到需要处理的一笔，点击“核查 / 处理”。在详情中点击“重新核查”读取原链上结果，符合条件后可点击“结束核查”；不符合条件时会显示具体原因。

普通本地记录进入此人工核查流程后，停止自动重试和单笔后台结案，防止漏掉另一笔历史尝试。尚未解决时，继续从详情点击“重新核查”核对全部历史尝试；这一保护在重启后仍然有效。

能确认最终失败或核实过期时，按实际证据处理。对仍无法确定结果的本地 TRC20 旧记录，全部发送尝试保存超过 24 小时后，可填写说明并确认人工归档。归档表示停止自动查询和重试，不表示转账失败，也不保证链上没有执行。原记录、哈希、签名审计和地址去重均保留，不会自动重发，手续费未知仍显示未知。之后可在详情中手动重新核查；若核实成功，记录更新为成功。

如果本笔已经执行成功、链上内容存在冲突、属于平台服务订单，或任务仍运行中，按钮会说明暂不可结束的原因。平台相关交易应先在平台核对原单，不能在客户端删除未结算费用。

绑定成功后会显示“已连接平台”，而不是“独立本地模式”。若只是填入绑定码、点击后出现错误，说明尚未完成绑定；处理提示后再试，绑定码过期时在平台重新生成。


## 平台未广播失败的单笔补发（1.3.4）

先暂停投放，再打开“投放记录”中的失败记录，点击“检查补发”。工具逐一核对原平台订单、同地址历史和旧签名；通过后显示原地址、合约、数量、服务费及执行费用上限。确认只会处理这一笔，不会启动扫描或发送其他等待记录。

平台取消但从未广播、费用已释放，且所有旧签名过期并通过链上查询，才有补发资格。出现成功、执行中、未知或冲突证据时按原因继续核查。旧的“重启已略过”记录必须没有任何发送证据且去重已解除，才不会阻挡本次补发。

1.3.4 会区分真实回执与“查询失败、等待以后补查”的纯标记。已确认归属旧签名、没有任何回执指标的补查标记会保留，并继续核对原订单及全部旧签名；不会只因存在这条标记就误报回执冲突。真实回执、哪怕为零的消耗数据，以及无法识别的记录仍继续拦截。若仍提示冲突，请按详情核查证据，不需要删除记录或清空去重。

确认过期或设置变化时须重新检查。点击后即记录唯一尝试；超时、断网、重启等情况只核对原订单，不自动再发。处理中可点击“停止后续操作”；已经签名或提交的记录会保留供核查。服务费与链上费用分开显示，初始提交失败原因也会保留。

如果上一轮手动补发因平台限制被拒绝，等待平台确认该轮未广播、已取消且费用已释放后，可以重新“检查补发”。旧签名仍须全部过期并核实未上链。每轮须取得新的确认并再次勾选，不复用旧确认、不自动重试。旧补发标记和签名按历史留存。程序运行中先暂停投放并取消自动恢复，详情会提示当前限制。
